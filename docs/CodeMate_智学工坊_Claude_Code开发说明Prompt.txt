你现在作为资深全栈工程师和产品设计师，协助我开发一个可演示的网页全栈项目。项目名称为“CodeMate 智学工坊”，Q 版数字人学习伙伴名称为“CodeBuddy”。请严格按照以下需求开发，不要随意扩大范围。第一版重点是能稳定运行、视觉完成度高、适合比赛展示，并支持 Mock 演示模式。 

一、项目定位
项目是“面向计算机科学与技术专业课程群的个性化学习资源生成与学习路径规划智能体系统”。它不是普通资料生成器，而是一个参考 OpenMAIC 风格的多智能体互动学习空间。系统通过 CodeBuddy 多轮自然语言对话了解学生情况，生成六维学习画像，结合计算机专业课程群知识结构生成个性化学习资源、规划学习路径，并通过轻量辅导评估展示学习进步。

二、技术栈
前端：React + TypeScript + Tailwind CSS。
路由：React Router。
动画：Framer Motion。
图标：Lucide React。
后端：FastAPI。
数据库：SQLite。
课程知识库：本地 JSON / Markdown。
大模型接口：统一 LLM Provider，支持 mock / claude / openai / qwen / deepseek 等可替换配置。默认使用 Mock 演示模式，保证没有 API Key 时也能完整演示。

三、整体 UI 风格
整体参考 OpenMAIC 的多智能体互动学习空间，而不是传统后台管理系统。采用“左侧统一导航栏 + 中间学习画布 + 右侧画像/智能体状态栏”的布局。视觉风格为浅色背景、蓝紫渐变主色、圆角卡片、轻微阴影、柔和动效、Markdown 渲染、代码块高亮、学习路径时间轴和智能体状态展示。

左侧导航栏固定为 6 项：
1. 首页
2. 学习画像
3. 课程中心
4. 资源生成
5. 学习路径
6. 辅导评估

四、页面 1：首页 Dashboard
首页包含五个区块：
1. 顶部介绍区：标题“CodeMate 智学工坊”；副标题“面向计算机科学与技术专业课程群的个性化学习资源智能体平台”；简介说明通过 CodeBuddy 多轮对话构建画像、生成资源、规划路径并辅导评估。
2. 课程群概览区：展示 6 门课程卡片：程序设计基础、数据结构与算法、计算机组成原理、操作系统、计算机网络、数据库系统。
3. 系统流程区：多轮对话 → 画像生成 → 课程诊断 → 资源生成 → 路径规划 → 辅导评估。
4. 多智能体协作区：展示 Profile Agent、Course Map Agent、Diagnosis Agent、Resource Agent、Code Practice Agent、Path Planning Agent、Assessment Agent。
5. 默认演示场景区：展示计算机专业学生从程序设计基础过渡到数据结构学习的场景。

五、页面 2：学习画像页
页面中间放置 Q 版数字人 CodeBuddy 和对话区，右侧展示学习画像草稿、缺失字段、诊断题和最终画像。
CodeBuddy 必须通过亲切、多轮自然语言对话持续提问，每轮只问 1-2 个问题。不要做成表单，也不要一次性让用户填完。CodeBuddy 应根据学生回答判断哪些信息还缺失，并继续温和追问，直到信息足够生成初始画像。

需要收集的信息包括：当前学习课程、已学课程、知识基础、学习困难、编程语言基础、学习方式偏好、学习目标、资源偏好等。之后通过轻量诊断题校准画像，例如递归代码输出判断、数组边界选择题、二叉树遍历顺序判断。

六维学习画像最终为：
1. 知识基础
2. 认知风格
3. 易错点特征
4. 实践能力
5. 学习目标
6. 资源偏好

注意：不要把六个维度都强行打分。知识基础和实践能力可以用星级、成长值、进度条展示；认知风格、易错点特征、学习目标、资源偏好主要用标签和卡片展示。不要使用“偏弱”“一般”等负面评价。画像不是大模型凭聊天直接打分，而是“多轮对话 + 轻量诊断题 + 学习任务表现”动态生成与更新。

六、页面 3：课程中心
课程中心采用“课程群地图 + 课程卡片 + 课程详情”的形式。包含 6 门课程：程序设计基础、数据结构与算法、计算机组成原理、操作系统、计算机网络、数据库系统。重点展示“程序设计基础 + 数据结构与算法”，其他课程作为课程群结构和跨课程关联支撑。
每张课程卡片显示课程简介、推荐学习阶段、先修课程、关联课程、核心知识点、可生成资源类型。
程序设计基础重点知识点：变量与数据类型、条件与循环、函数、数组、递归、基础调试。
数据结构与算法重点知识点：线性表、栈与队列、树与二叉树、递归思想、排序算法、查找算法、时间复杂度。

七、页面 4：资源生成
页面采用“资源生成工作台”。用户选择课程、知识点、难度、编程语言、讲解方式和资源类型。默认演示知识点围绕“程序设计基础—递归”和“数据结构与算法—二叉树遍历”。
资源类型固定为 6 类：
1. 个性化讲解文档
2. 知识点思维导图
3. 代码示例与注释
4. 分层练习题
5. 拓展阅读资料
6. 项目式学习案例
右侧展示智能体生成状态，例如 Diagnosis Agent 分析学习困难，Resource Agent 生成讲义，Code Practice Agent 生成代码示例，Assessment Agent 生成练习题。

八、页面 5：学习路径
学习路径页面不是单纯路线图，而是“学习路径 + 个性化资源推送 + 成长目标展示”。默认路径名称为“从程序设计基础到数据结构入门的成长路径”。路径节点包括：
1. 函数调用基础
2. 数组与循环巩固
3. 递归概念与调用栈
4. 二叉树结构理解
5. 二叉树遍历代码实现
6. 分层练习与错题修正
7. 文件目录树项目案例
每个节点展示所属课程、学习目标、推荐资源、预计学习时间、完成后可能提升的画像维度、当前状态。

九、页面 6：辅导评估
该页面做轻量可演示版本。中间是智能辅导问答区，右侧是小测评估和成长反馈区。智能辅导回答要结合学生画像，结构为：亲切回应 → 说明将采用的解释方式 → 分步骤讲解 → 代码或图示示例 → 推荐资源 → 提供小练习。
小测提交后展示本次得分、正确题目、需要继续练习的知识点、推荐补救资源、成长值变化和徽章激励。例如“知识基础 +5，实践能力 +4，点亮徽章：二叉树探索者”。

十、默认演示学生与 Mock 数据
内置默认学生：李同学，计算机科学与技术专业大二学生。她正在学习程序设计基础和数据结构与算法，会一些 Python 和 C 语言基础，但对函数调用过程、递归、数组操作和二叉树遍历理解不够清晰，写代码时经常需要参考示例。她更喜欢图示讲解、代码案例和分层练习题，希望系统帮助她生成学习资源，并规划一条从程序设计基础过渡到数据结构学习的路径。

默认画像：
知识基础：★★★☆☆，62/100，待诊断题校准。
实践能力：★★★☆☆，58/100，待代码练习校准。
认知风格：图示优先、示例驱动、分步骤解释。
易错点特征：递归出口、函数调用顺序、数组边界、遍历顺序。
学习目标：掌握递归、数组和二叉树遍历，完成课程练习。
资源偏好：代码案例、思维导图、分层练习题、简洁讲义。

十一、多智能体设计
实现上第一版可以用后端服务模块模拟多智能体，不必引入复杂 Agent 框架，但前端需要展示协作过程。模块建议：
Profile Agent → profile_service.py
Course Map Agent → course_service.py
Diagnosis Agent → diagnosis_service.py
Resource Agent → resource_service.py
Code Practice Agent → code_service.py
Path Planning Agent → path_service.py
Assessment Agent → assessment_service.py

十二、API 建议
POST /api/profile/chat：画像多轮对话，返回下一轮追问、已提取字段、缺失字段。
POST /api/profile/generate：生成完整初始学习画像。
GET /api/courses：返回课程列表。
GET /api/courses/{course_id}：返回课程详情、知识点和先修关系。
POST /api/resources/generate：生成资源卡片和内容。
POST /api/path/generate：生成学习路径、资源推送和成长目标。
POST /api/tutor/chat：结合画像进行个性化问答。
POST /api/assessment/submit：提交小测，返回反馈、成长值变化和徽章。

十三、开发阶段
请按 7 个阶段开发，不要一次性写巨大混乱代码：
1. 项目骨架搭建：React + FastAPI + SQLite + 左侧导航栏 + 6 页面路由 + Mock 数据联通。
2. 首页与整体 UI 风格：参考 OpenMAIC 完成首页、课程群概览、多智能体流程展示。
3. CodeBuddy 学习画像页：Q 版数字人、多轮自然语言追问、缺失字段判断、轻量诊断题、六维画像。
4. 课程中心页：6 门课程卡片、课程详情、先修关系、课程群地图。
5. 资源生成页：6 类资源生成、资源卡片、智能体状态栏。
6. 学习路径页：路径节点、个性化资源推送、预计成长值、学习状态。
7. 辅导评估页与演示优化：个性化问答、小测反馈、分数提升、星级进度、徽章激励、Mock 模式兜底。
